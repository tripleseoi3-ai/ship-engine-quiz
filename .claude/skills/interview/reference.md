# 1단계: INTERVIEW

목적: 사용자의 머릿속에만 있는 것을 밖으로 꺼내 기록한다. 설계하지 않는다. 해결책을 제안하지 않는다.

## 진행 방식

- **한 번에 3~5개.** 질문 20개를 한꺼번에 던지면 사용자는 답을 포기한다.
- **먼저 조사하고 묻는다.** 저장소·파일·기존 문서를 읽어서 알 수 있는 것은 질문 대상이 아니다.
  대신 "제가 확인해보니 X인데 맞습니까?" 형태로 검증만 받는다.
- **답을 되풀이해 확인한다.** 한 라운드가 끝나면 이해한 바를 3~4줄로 되짚고 틀린 곳을 지적받는다.
- **"모르겠다"도 답이다.** 그대로 `미결정`에 기록한다. 대신 채워 넣지 않는다.

## 질문 영역 (순서대로)

### A. 문제
- 지금 무엇이 불편한가? 구체적인 최근 사례 하나를 말해달라.
- 그 일이 얼마나 자주 일어나는가?
- 지금은 어떻게 처리하고 있는가? (기존 우회 방법)

### B. 사용자
- 누가 쓰는가? 몇 명인가?
- 그 사람의 기술 수준은? (터미널을 쓰는가, 엑셀만 쓰는가)
- 언제, 어디서 쓰는가? (한 달에 한 번인가, 매일인가)

### C. 성공
- 이게 잘 됐다는 걸 무엇으로 알 수 있는가?
- 그 판단을 숫자로 바꾸면 무엇인가? (시간, 건수, 오류율)
- 만들고 나서 누구에게 보여줄 것인가?

### D. 범위 밖
- 이번에 **안 할 것**은 무엇인가?
- 나중에 하고 싶지만 지금은 아닌 것은?
- 절대 건드리면 안 되는 것은? (기존 데이터, 운영 중 시스템)

### E. 제약
- 마감이 있는가?
- 써야 하는 언어·도구·환경이 정해져 있는가?
- 쓸 수 없는 것은? (예: 외부 API 금지, 인터넷 없는 PC)
- 다뤄야 하는 데이터에 개인정보가 있는가?

### F. 기존 자산
- 이미 있는 코드·문서·데이터 중 재사용할 것은?
- 참고할 만한 비슷한 것이 있는가? (사내 도구, 다른 서비스)

### G. 실패 시나리오
- 이게 잘못 동작하면 무슨 일이 벌어지는가?
- 최악의 경우는? (데이터 유실, 잘못된 성적 산출 등)

## 종료 조건

C(성공), D(범위 밖), E(제약)가 모두 채워졌으면 종료한다.
A/B/F/G에 빈칸이 있어도 사용자가 "충분하다"고 하면 `미결정`에 남기고 넘어간다.

## 안티패턴

| 하지 말 것 | 대신 |
|---|---|
| "어떻게 구현할까요?" 를 인터뷰에서 묻기 | 3단계(SDD)까지 미룬다 |
| 사용자가 말하지 않은 기능을 추가로 제안 | 다 듣고 나서 2단계에서 비목표로 정리 |
| 예/아니오로만 답하게 하는 질문 | "최근 사례를 하나 말해달라" 같은 서술형 |
| 답 없는 항목을 상식으로 채우기 | `미결정: 확인 필요` 로 남긴다 |
