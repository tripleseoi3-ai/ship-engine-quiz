# 1단계: INTERVIEW

담당 에이전트: **`interviewer`**
산출물: `docs/specs/<YYYY-MM-DD>-<슬러그>/01-interview.md`
다음 단계: `goal`

## 역할 분담

| 하는 일 | 누가 |
|---|---|
| 저장소 조사, 질문 라운드 작성, 답변 기록 | `interviewer` 에이전트 |
| 질문을 사용자에게 전달하고 답변을 받아오기 | 메인 세션 (당신) |

서브에이전트는 사용자와 직접 말할 수 없다. 그래서 인터뷰는 **에이전트 호출 → 사용자에게 질문 → 답변을 다시 에이전트에 전달**을 반복한다.

## 절차

### 1. 질문 라운드 받기

Agent 도구로 `subagent_type: interviewer` 를 호출한다:

```
MODE: PREPARE
대상: <사용자가 말한 주제 한 줄>
작업 디렉터리: <저장소 경로>
기존 인터뷰 파일: <경로 또는 "없음">
```

### 2. 사용자에게 그대로 묻기

에이전트가 돌려준 질문 문장을 **줄이거나 바꾸지 말고** 그대로 사용자에게 낸다.
"조사로 이미 확인한 것" 항목도 같이 보여준다 — 사용자가 틀린 전제를 바로잡을 기회다.
한 번에 3~5개를 넘기지 않는다.

### 3. 답변 기록

사용자 답변을 받으면 다시 호출한다:

```
MODE: RECORD
답변 원문:
<사용자가 쓴 그대로 붙여넣기>
```

원문을 다듬어서 넘기지 않는다. 나중에 해석이 갈릴 때 원문이 근거다.

### 4. 반복 / 종료

에이전트가 "종료 가능"을 보고할 때까지 1~3을 반복한다.
종료 조건: **C(성공 기준) · D(범위 밖) · E(제약)** 세 영역이 다 채워졌을 때.
사용자가 "이 정도면 됐다"고 하면 빈 영역을 `미결정` 으로 남기고 넘어간다.

## 규칙

- 코드나 파일을 읽어서 알 수 있는 것은 묻지 않는다. 확인만 받는다.
- 사용자가 답하지 않은 것을 추측으로 채우지 않는다. `미결정` 에 남긴다.
- 인터뷰 중에 설계·구현 이야기를 시작하지 않는다. 3단계 몫이다.

세부 지침은 `reference.md`, 문서 틀은 `template.md`.

## 끝나면

`01-interview.md` 경로와 요약 3~4줄을 사용자에게 보여주고, 2단계 `goal` 로 넘어갈지 묻는다.

## 에이전트를 못 찾으면

`.claude/agents/` 의 에이전트는 **세션이 시작될 때 등록된다.** 방금 추가했다면 `subagent_type: interviewer` 호출이 "Agent type not found" 로 실패한다.
그때는 둘 중 하나로 처리한다:

- 세션을 새로 시작한다 (권장). 그러면 `interviewer` 이 목록에 뜬다.
- 급하면 `subagent_type: general-purpose` 로 호출하되, 프롬프트 맨 앞에 `.claude/agents/interviewer.md` 를 먼저 읽고 그 지침을 그대로 따르라고 지시한다.
